# 给流水线加一道确定性门

模型说「我核过了」不是门。门必须是一个对产物做纯函数的脚本：输入是盘上的文件，输出是 fail 数与逐条明细，同一个输入永远同一个结果。下面是把这种门加进多岗流水线的顺序与坑。

## 一、先写成独立脚本，再接线

1. **单文件、只依赖标准库、带 `__main__` CLI**，参数是案件目录。这样能在零成本下反复跑。
2. **拿一个已经跑完的真实案件当夹具**（`cases/<slug>/out/` 里现成的 `citations.md` + 成稿），在接进引擎之前把解析器调对。这一步能抓到原始数据里的全部脏格式，且不花任何模型调用。
3. 解析器稳定后再写 `run(out_dir) -> dict`，返回 `{status, fails, ...明细}`，由引擎调用。
4. 报告落 `out/<门名>.md`，**必须能被律师单独看**：抬头写清「核验表 n 条 / 成稿 m 处」，正文分级列表，末尾一行统计 + 本门 fail 数。

## 二、接线顺序（四件事都要做，少一件门就是摆设）

| 时机 | 做什么 | 为什么 |
|---|---|---|
| 生产者岗落盘后 | 立刻跑一次门 | 消费者岗开工时要能看到判定 |
| 消费者岗开工前 | 若门文件不存在就再跑一次 | 局部重跑（`--only 60`）时上游会被跳过 |
| 回改岗改完后 | **先刷新门，再跑审核岗** | 不刷新 = 审核岗拿改稿前的判定，`gate.md` 写「门 fail 2」而门文件已是 PASS，两份文件互相打架 |
| 汇总 | `总 fail = 模型门禁 fail + 确定性门 fail` | 否则门只在报告里红，不动回改循环 |

配套：把明细翻成回改岗能执行的一句话塞进它的 `corrective`（「第 50 行《行政处罚法》第 40 条……一律删除；确需提及只写规范名称与『原文待核』，不得带条号」）。只给数量，模型会猜。

## 三、状态三态，不是两态

- `PASS` / `FAIL` / **`BLOCKED`**（输入文件缺失、门自己跑崩）。
- BLOCKED 不是 PASS：未核＝未证。
- 门抛异常时记 **1 项 fail**，不静默放行——fail-open 的门比没有门更坏。
- 交付包里要把门状态写进清单首屏，不只留在附件里。

## 四、引用文本解析：实测踩过的六个格式

1. **中文数字**：`第四十四条` / `一百零八条` / `第十一条`。标准解析：遇「十」进位 ×10、遇「百」×100，「零/〇」跳过。写完先自测 11/44/82/108。
2. **跨表格列**：核验表把规范名与条款分放两格（`| 《听证办法》 | 第五条第二款 | 准确 |`）。书名号后允许跳过一个 `|` 再取条款。
3. **并列引用**：`《行政处罚法》第四十条及第五十四条` —— 第二个条款没有书名号，必须跟着第一个走；分隔符集合 `[、，,及和与或者]`。
4. **简称**：`《条例》第十八条`。按后缀唯一匹配到全名（`条例` → `企业信息公示暂行条例`）；匹配到多个就记「未解析」，既不判 fail 也不判 pass。
5. **附录分层**：附录一是「法律依据对照表」，本身就带状态列，按**自报冲突**查（同一行自称已核/准确而核验表判否）；附录二、附录三是实质内容（救济途径里真引条文），按正文严格查。混在一起查会产生大量假 fail。
6. **元叙述污染**：模型会在文末「回改说明」里原样抄出被拒的条号（「原稿并未出现第 40 条、第 54 条……」）。两道处理：落盘前剥掉文末内部节（先解析黑板再剥，否则黑板要点一起丢）；门本身也只扫正文与附录。

## 五、三类别名，别把豁免做成漏洞

判 fail 之前先分类，三类只记不计 fail，且**全部列进报告**供律师目视：

- **转述对方援引**（引用前 24 字含「援引/载明/告知公告/贵局」）——那不是我方主张依据。
- **原文自带待核标记**（引用后 120 字内含「待核/未核/不作原文引用」）——模型已自认未核，判 fail 是重复惩罚。
- **附录一对照表**——按自报冲突查，见上。

豁免窗口要窄：放宽到整段，模型学会加个「待核」就绕过。窗口按字数卡死。

## 六、单测怎么写

一个规则一个用例，**每个用例都要会因为「改坏了」而变红**。最小集：

- 无输入 → BLOCKED（不是 PASS）
- 全部命中白名单 → PASS
- 核验表判否 + 正文引用 → FAIL，且**行号指到原文行**
- 每类豁免各一例，断言 `status == pass` 且 `len(context) == 1`
- 跨列表格、中文数字、简称唯一/不唯一
- 白名单「准确（就所附片段而言）」仍算可引用

写测试时注意成稿有最小长度阈值（如 200 字节）才被解析，短样本要补到阈值以上，否则全落到 BLOCKED 分支，测试变成空转。

## 七、边界要写进报告，不要假装全覆盖

至少披露四类：

1. **只查资格，不查内容**：门判「这条有没有资格被引用」，逐字是否一致仍是引用核验岗的事。
2. **简称指代**：解析不了的记「未解析」，不判 pass。
3. **条款粒度**：成稿写到「条」而白名单只有某几款时，有任一款准确即放行；写到具体款/项则要求那一款/项被判准确。
4. **前置门的强制绕过**：`--force`（覆盖重跑）**不得**顺手关掉前置门；材料不全时重跑十遍出来的还是演练稿。要放行另设 `intake_override` / `--allow-empty`，并在对外场合标「模板演练」。
