# 工序框架的跨域移植

这套 DAG 的价值不在“法律”，而在骨架：**事实 → 规则源 → 反方 → 类案 → 冲突 → 沿革 → 论证 → 红队 → 引用核验 → 成稿 → 门禁**。凡是“规则密集 + 有人审你 + 错了要付钱”的领域，骨架都能直接搬。

## 三个准入条件（缺一条就不要搬）

| 条件 | 判据 | 不满足会怎样 |
|---|---|---|
| 有官方原文 | 每条主张都能落到一份可逐字引用的文书/标准/词表 | 引用核验无处可核，退化成“AI 说得挺像” |
| 对抗性真实 | 存在一个会挑错、有权驳回的对手（机关、医保审核员、甲方合规） | 红队无人可扮，输出没有压力测试 |
| 结果可判定 | 门禁每一条都能写“过/不过”，不靠审美 | 清单变成空话，交付质量不可复现 |

## 四步移植法

1. **定规则源**：列出该域的全部官方文本与版本（法律→法规库；病案→ICD 表、结算清单规范、分组方案、监管规则库）。版本必须带生效日期，否则冲突审查会引旧版。
2. **定反方**：谁审你、依据什么驳你。把“他会怎么问”写成一张固定清单，这才是红队卡的输入。
3. **定冲突面**：该域最常见的“两套规矩打架”——新旧版本、行业版 vs 国家版、上位 vs 下位、定义不一致。冲突审查是扩张空间的战场，省掉它这套流程就只剩格式。
4. **定门禁**：把“老手的直觉”逐条改写成可判定的检查项。条数不必是 26，但每条必须能由第三方复核。

| # | 法律线 | 通用列 | 病案编码 |

| 01 | 事实包 | 只录可核内容，缺的标“待补” | 病历结构化包 |

| 03 | 不利法源 | 替对方找依据 | 病历中不支持该编码的表述 |
| 04 | 类案与倾向 | 同类的既往处理结果 | 同病种/同组历史入组 |
| 05 | 规范冲突 | 两套规矩谁说了算 | 临床版 vs 医保版；2.0 vs 3.0 |
| 06 | 概念沿革 | 定义随版本怎么变 | 编码扩容、更名、拆分 |

| 08 | 红队 | 扮演审核人逐条攻击 | 医保审核员视角质疑 |
| 09 | 引用核验 | 核不上就删 | 规则原文与版本核验 |
| 10 | 成稿 | 对外可交的成品 | 质控报告 + 应答材料 |

## 映射表（法律 → 通用列 → 策略/因子证伪）

| # | 法律线 | 通用列 | 策略/因子证伪 |
|---|---|---|---|
| 01 | 事实包 | 只录可核内容，缺的标“待补” | 数据事实包：样本、区间、观测数、复权、成本与成交假设 |
| 02 | 有利法源 | 官方规则与版本 | IC / 分层 / 异源交叉 / 样本外 |
| 03 | 不利法源 | 替对方找依据 | 反例年份、成本敏感性、集中度、前视、幸存者、尝试次数 |
| 04 | 类案与倾向 | 同类的既往处理结果 | 同类策略的公开结果（论文、基金、产品披露） |
| 05 | 规范冲突 | 两套规矩谁说了算 | 口径冲突：IC vs 超额 vs 绝对、复权方式、日历、买卖时点 |
| 06 | 概念沿革 | 定义随版本怎么变 | 数据源更换、涨跌停/印花税/ST 规则变更、指数成分调整 |
| 07 | 论证 | 每条主张落到原文 | 每条结论落到一条可重算命令 |
| 08 | 红队 | 扮演审核人逐条攻击 | 扮三方：卖方（怎么卖出去）、买方（凭什么信）、审稿人（怎么毙掉） |
| 09 | 引用核验 | 核不上就删 | 数字核验：从库里重算，对不上就删（无重算命令＝无数字） |
| 10 | 成稿 | 对外可交的成品 | 检验报告 + 数字可信度速查表 |
| 11 | 门禁 | checklist 唯一定义 | 分级结论 L0–L5，只允许这几种字样 |

准入条件在本域的对应：有可复现数据（取代“有官方原文”）／市场结果与独立审查者构成对抗（取代“有权驳回的对手”）／每条门禁能写“过/不过”（不变）。

## 移植后必须改的三处（不能照搬）

- **反方不再是人**。法律有一份会驳回你的机构；研究里没人会当场驳回你的报告，所以“谁有权说这份研究是错的”必须显式指定一个角色（买方视角/审稿人视角/资金结果），否则红队卡自己就空转了。
- **门禁从二值变分级**。法律只有“可提交/不可提交”；研究多一个“证据不足”的真实状态，硬做二值会逼人把不确定编成结论。
- **引用核验的对象从条文变成数字**。报告里每个数字挂一条重算命令，是这一域等价于“无原文＝无引用”的硬约束。

## 输出形态要跟着换

法律线的成品是“为一方争取利益的文书”；搬到质控域后，成品是**按风险排序的清单**（必改／建议改／存疑），因为读者不是法官而是要干活的人。照搬申辩书的论证腔，会被读成“这 AI 在教我做事”。

## 移植时最容易走偏的一步

先写产品/方案文档，再想工序——写出来一定是“AI + 行业”的空话。**先做映射表**：左列十道工序，右列本域对应物，填不满的格子就是没想清楚的地方，填满之后再写文档。
