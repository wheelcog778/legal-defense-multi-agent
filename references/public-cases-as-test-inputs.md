# 公开处罚决定书 → 测试输入

手上没有真实客户材料、又要验证流水线（或别的 agent）会不会退化时，用政府网站公示的处罚决定书当输入。目标是“给一份不利文书，看它能不能拆”，不是办案。

## 选案标准

一批 3–4 个就够，但要错开：

- **法域分散**：广告/反不正当竞争、食品标签产地、消费者权益、化妆品或医疗器械、互联网信息服务——各取一个，别四个都是虚假宣传。
- **至少 1 个带原文硬伤**：条款引错、依据与认定对不上、裁量一句话不说理由。这是红队岗与引用核验岗的试纸，抓不到就说明两岗都在走过场。
- **至少 1 个一案多因**：多个违法行为并罚、减轻处罚、违法所得“无法计算”。看 15 冲突审查与 20 抗辩构建会不会被绕晕。
- **至少 1 个金额极小**（几百元罚款）：检验它是否还肯按同一套工序认真做，还是直接敷衍。
- 优先选带**完整证据清单段落**（“上述事实，主要有以下证据证明：1.…2.…”）的决定书，事实卡才有东西可拆。

## 告知阶段案的案源（决定书测不到的那条路）

四个决定书案例也覆盖不到"收到告知书→写申辩意见"这条主路径。真件来源按可得性排：

1. **各地市监局的"行政处罚告知书送达公告"**——中等批量、内容最全：公告对下落不明当事人送达时，正文通常照抄拟处罚的事实、理由、依据、幅度与申辩期限，等于一份完整告知书。检索 `行政处罚告知公告 吊销营业执照 2026`。
2. **复议决定书**——常复述告知书文号与送达日，少见全文。
3. **裁判文书**——逐字引告知书全文的少，多出现在"告知程序是否合法"成为争点的判决里。
4. **当事人手里那份**——最真，脱敏即可。

取告知书案要额外注意两点：**公告送达的送达日＝公告发布日 + 30 日**（视为送达），申辩期从视为送达日起算，不能拿落款日当送达日；公告常**不载告知书文号**，这本身就是可写进争点的瑕疵。

## 取数

1. 检索词形如 `行政处罚决定书 全文 <机关类型> <违法类型> filetype:pdf`。公示 PDF 通常带“第 X 页 共 Y 页”页眉，说明有文本层，能抽。
2. **不要让网页抓取工具直接吃 gov PDF**：常见 404、读超时，或那个 `.pdf` 地址其实返回站点导航页（真正的附件链接在页面里另一处）。用 curl 落盘再验：

```bash
curl -sS -L --max-time 60 -A "Mozilla/5.0" -o case.pdf "<url>"
file case.pdf    # 必须显示 PDF document，出现 HTML 就是拿到了导航页
```

3. 抽取（需要一个带 pip 的 Python 环境；Windows 上用 `py -3` 替换 `python3`）：

```bash
python3 -m pip install pypdf --quiet
python3 -c "from pypdf import PdfReader; import pathlib,sys; r=PdfReader(sys.argv[1]); pathlib.Path(sys.argv[1]+'.txt').write_text('\n'.join(p.extract_text() or '' for p in r.pages), encoding='utf-8')" case.pdf
```

## 清理（抽取结果一定脏）

按顺序：

1. 删页眉 `第\s*\d+\s*页\s*共\s*\d+\s*页`。
2. 删页码：某行是纯数字，且**落在该页前两条或后两条以内**、前一行不以 `年/月/日/〕/（` 结尾、后一行不以 `号/年/月/日/页` 开头 → 它是混进正文的页码。
   **只删页首页尾，不要全文扫**：有些 PDF（如 WPS 子集字体）把每个词都排成单独一行，全文横扫会把“共 89 页”“2026 年 4 月 15 日”“〔2026〕7-02 号”里的真数字一并吃掉，交付方拿到的是被抽空的稿子。按页抽、按页删，抽完必检年份、页数、文号三类数字是否还在。
3. 全角 `９`（U+FF19）在部分 PDF 里被当成顿号/逗号抽出来 → 替换成 `，`。
4. 汉字与全角标点之间的空格全删；数字之间的空格也删（`202 6年` → `2026年`）。
5. 在结构标记前插空行分段：`当事人：`、`经查`、`上述事实`、`另查明`、`本局认为`、`依据《`、`综上`、`当事人应当`、`如你`、`本文书一式`。
6. **必检**：抽完随手读三段，确认没把“罚款20000元”这类数字连读删掉、没有残留页码、没有整段粘成一行。

## 每个案例的文件形态

```
测试案例/NN-简称/
├── meta.json
└── input/
    ├── 行政处罚决定书-<文号>.md     # 清理稿，仅供阅读
    └── 原件-<文号>.pdf              # 唯一可信原文
```

- `.md` 顶部固定一段【测试材料说明】：这是**已作出的处罚决定书，不是告知书**；用法是逆向——把机关的事实认定与说理当攻击面，模拟复议/诉讼阶段找漏洞；期限口径按已送达决定书算（复议 60 日、诉讼 6 个月）。再接一张表：文号 / 作出机关 / 作出日期 / 原件 / 来源 URL / 主要法律依据。
- `meta.json` 固定六键：`title`、`goal`、`材料性质`、`本包提供`、`待补`（当事人陈述、证据清单、送达凭证）、`考察点`（这个案子专门测哪一岗、怎么测）。
- 口径说明里写明“逐字引用以 PDF 为准，md 只用于读”，否则后面 40 引用核验会拿清理稿当原文。

## 打包与说明

- 目录：`00-测试说明.md` 放根；流水线本体一个目录（SKILL.md + references/ + roles/ + 脚本 + checklist + 手册）；`测试案例/` 平铺。
- 说明里必须有四条：①两条路径（无 kanban 的 agent 用手册逐段喂；有 kanban 的用 `build_case.py`，前提是 `researcher/analyst/verifier/writer` 四个 assignee 存在、workspace 用 `dir:` 绝对路径）；②案例表；③三条硬声明（决定书≠告知书、文本可能还原不准、不含当事人材料——这恰好用来测 00 卡会不会写【待补】）；④回报清单。
- 回报清单只问能定位退化的四件事：00 有没有写【待补】、11 第一行有没有点名漏项、预埋/原文那个错有没有被抓到、60 结论行是否只有“可提交/不可提交”。再补一句“哪一岗最慢、哪一岗交的是空话”。
- zip 用 Python `zipfile` 生成（文件名带 UTF-8 标志），`unzip -l` 看中文有没有乱码，`testzip()` 验完整性。别用 shell zip 或资源管理器压中文目录——出过分发包里文件名全乱码的情况。

## 打包后三查（每条都真出过错，且测试跑不出来）

1. **案例数标题 = 表格行数**。说明里写“四个案例”而表里已经五行，读的人直接漏掉第五个；改一版就重数一次。
2. **无原件 PDF 的案要单独声明**。网页公告类案子没有 PDF，但硬声明里写着“input 里有原件 PDF”——结果 40 岗那一案无法执行。逐案写清“哪几案有 PDF、哪几案只有网页（原件非 PDF）”，并规定无 PDF 的案子 #12/#13 判 blocked。
3. **旧版本的产物不能留在可能被当样张的位置**。`cases/<旧案>/out/gate.md` 用旧契约（项数、判定分类、结论行格式全变过），按新清单跑的人会照拄错的格式。在文件头加“旧契约、不得作样张”标记，或整体移进 `_归档/`。

配套：包根放一个 `preflight.py`，一条命令查岗位卡数/门禁项数/三处版本同源/案例完整性（有无 meta、有无原件），把“人自己去比”的几步变成机器输出。

## 别做的事

- 不把清理稿当原文引用。
- 不因为“官方文书”就默认它没有错：公示的决定书本身就常有条款引错，这正是最好的测试点，但要在说明里标清“这是原文错误，不是我们造的”。
- 不用这些公开案例对外宣称“办成过”。
