# 法律多智能体框架 · v1.5.1

> 让你输的那一条，是你没读到的那一条。

一套可复用的行政处罚申辩 / 行政诉讼流水线：事实 → 有利法源 → **不利法源** → **类案** →
**规范冲突** → **沿革与不确定概念** → 抗辩构建 → **红队** → **引用核验** → 成稿 → 门禁。

十一张岗位卡（Markdown）、三个零依赖 Python 脚本、一张 26 项提交门禁。跑在
[Hermes](https://hermes-agent.nousresearch.com/docs) 的 kanban 板上；配 `manual/` 里的手册，
任何聊天模型都能跑，不需要任何工具。

## 为什么不是"一个 agent 写一份文书"

因为单一链路只会朝有利方向检索。真实办案里，让对方输的往往不是你的论证，是你漏掉的那一条。

- **换条。** 你把全文功力都压在《暂行规定》第六条上。机关回复时改用《实施办法》第十二条 +
  第二十二条第三款——那条直接罚个人。你写的每一段，现在都在讲一部没被适用的规范；而重读自己的稿子
  永远看不出这一点，因为稿子里从来没有那一条。
- **概念漂移。** 案子赖以成立的那个概念，在规范的旧版与新版之间被重新定义。用今天的定义去论证，
  对方只需回一句：行为按行为时的版本评价——从旧兼从轻，《行政处罚法》第三十七条。
- **引用。** 一个记得大概的条号，配一个看上去合理的修订年份。承重段落里错一条，整份文书在对方眼里
  就不值得细读了，其余写得多好都一样。

这三件事都不是"写稿的那条链"能看见的。所以它们各占一个岗位，由不同角色执行，最后由一道可以拒绝
交付的门禁收口。

## 十一道工序

```
00 事实包 (researcher)
 ├─ 10 有利法源 (researcher) ─┐
 ├─ 11 不利法源 (analyst)    ─┤
 └─ 12 类案裁判 (analyst)    ─┤
                              ├─ 15 规范冲突 (verifier) ─┐
                              └─ 16 沿革概念 (verifier)  ─┴─ 20 抗辩路径 (analyst)
                                                               ├─ 30 红队 (verifier)
                                                               └─ 40 引用核验 (verifier)
                                                                   └─ 50 成稿 (writer)
                                                                       └─ 60 门禁 (verifier)
```

`11` 岗的第一行必须点名前一稿漏了哪一条。只罗列法条而不点名漏项，说明这一岗退化成了普通检索，
本次运行的对抗性等于零。


## 用法

**路径一：任何模型，不需要工具。** 读 `manual/行政处罚申辩十道工序.pdf`，把十段提示词按顺序喂给
手上的模型。每段都自包含（角色 + 输入 + 输出格式 + 铁律），不写"参见上一步"。

**路径二：Hermes kanban。**

```bash
python3 preflight.py                     # 岗位卡、门禁项数、版本、案例完整性
mkdir -p cases/<slug>/input cases/<slug>/out
python3 build_case.py cases/<slug>       # 需要 researcher/analyst/verifier/writer 四个 assignee
bash run.sh cases/<slug>
```

`preflight.py --kanban` 会额外检查板上四个 assignee 是否存在。`build_case.py` 幂等：同一案子重跑
不会重复建卡。

## 门禁

- **两张表按产出选。** 文书类用表 A（26 项），救济窗口说明用表 B（12 项）。选错表＝整张门禁作废。
- **四种判定。** pass / fail / n/a / blocked。n/a 只限"材料本包没有"；blocked 只限"该核而通道不可用"。
  两者不能互相顶替。
- **`fail 0` 但 `blocked > 0` 仍是不可提交。** 未核＝未证。
- **结论行只许有结论。** 禁止"可先作为初稿递交""基本可提交"这类软着陆尾巴。只有
  `可提交（fail 0，阻断 0，blocked 0）` 或 `不可提交（fail n，阻断 B1/0，blocked k）`。
- **期限是算术，不是措辞。** 只写"复议 60 日"不算核过期限；门禁要求按送达日算出届满日与剩余天数。

## 这套东西现在的证据等级

写在最前面，因为它决定了你该怎么用它。

- **没有对照实验。** A/B 研究已预注册、判死线在任何数据之前写死（检出率差 < 20 个百分点、
  误报 +15 个百分点、成本 > 5 倍即判"没用"），但**还没跑**。这里没有任何证据支持"这套流水线比
  单模型一次成稿更好"——那是假设，不是结论。
- **没有律师复核。** 0 案。
- **没有当事人原件。** 0 案。测试中所有期限结论，送达日都是我们自己推定的。
- **真跑过的是：** 开发期四个真实公开的处罚决定书端到端跑通，外加三轮独立 agent 外测（换模型、独立环境）
  验可移植性。这能证明流程跑得通、能抓到真实引错；不能证明它对没见过的案子是对的，
  而且那四案参与过开发，不是留出样本。
- **不能替代律师，也不构成法律意见。** 期限很短（陈述申辩、复议 60 日、诉讼 6 个月），阶段判错
  整份文书白写。先判阶段，再动笔。
- **只适用于中国行政法。** 骨架可以搬到别的"有官方原文、引错就全废、结果可判定"的规则域
  （见 `references/framework-porting.md`），但内容不能搬。

## 三条铁律

1. **每条引用必须是原文**，不是大意。核不上原文的引用等于没有。
2. **不利检索先于构建。** 先知道对方能怎么打，再决定说什么。
3. **门禁不过不提交。** `gate.md` 里有一个 fail，就回去改，不改就别递。

## 先判程序阶段

- 收到《告知书》→ 申辩阶段，产出陈述申辩意见书。
- 收到《决定书》、复议期未过 → 复议阶段，产出行政复议申请书。
- 复议期已过、诉讼期未过 → 诉讼阶段，产出行政起诉状。
- 两期都过 → 救济窗口关闭，先出"窗口说明"，别再写申辩稿。

00 卡必须按送达日（无凭证则按落款日推定）算出复议 60 日、起诉 6 个月的届满日与剩余天数。
只写"60 日"不算核过期限。
